# NEED IT — Spring Boot + MySQL + JPA 연동 준비본

## 이 파일의 상태
- **기존 UI와 시연 기능을 유지**한 채 HTML/CSS/JS를 파일로 분리했습니다.
- `js/app.js`는 기존 시연용 코드입니다. **백엔드 연동이 아직 완료된 상태는 아닙니다.**
- `js/api-client.js`는 서버 연동을 위한 공통 클라이언트와 API 호출 예시입니다.
- `js/config.js`에서 `API_BASE_URL`을 변경합니다.
- CSS는 원래 적용 순서와 화면을 유지하기 위해 여러 파일로 분리했습니다. 추후 정리할 수 있습니다.

## 로컬 실행
프론트엔드 폴더에서 `python3 -m http.server 5500` 실행 후 브라우저에서 `http://localhost:5500` 접속.
백엔드는 `http://localhost:8080` 실행. Spring Security에서 CORS 허용 Origin을 `http://localhost:5500`으로 설정합니다. 쿠키 인증을 사용한다면 credentials와 SameSite/CSRF 정책도 일치시켜야 합니다.

## 권장 REST API 계약 (예시 — 실제 컨트롤러에 맞춰 조정)
| 기능 | 메서드 | URL |
|---|---|---|
| 회원가입 | POST | /api/auth/signup |
| 로그인 | POST | /api/auth/login |
| 내 정보 | GET | /api/members/me |
| 내 정보 수정 | PATCH | /api/members/me |
| 요청 목록 | GET | /api/requests |
| 요청 상세 | GET | /api/requests/{id} |
| 요청 등록 | POST | /api/requests |
| 요청 수정 | PATCH | /api/requests/{id} |
| 요청 삭제 | DELETE | /api/requests/{id} |
| 요청 마감 | PATCH | /api/requests/{id}/close |
| 나눔 제안 | POST | /api/requests/{id}/offers |
| 제안 상태 변경 | PATCH | /api/offers/{id}/status |
| 이미지 업로드 | POST | /api/uploads (multipart/form-data) |
| 신고 접수 | POST | /api/reports |
| 관리자 신고 조회 | GET | /api/admin/reports |

## 작업 순서
1. 백엔드 Entity / DTO / Controller 설계 후 API 명세 확정
2. `js/app.js`에서 회원가입·로그인·프로필의 localStorage 로직을 API로 교체
3. 요청 글 작성/목록/상세/수정/삭제를 API로 교체
4. 이미지 업로드, 나눔 제안, 상태 변경 연결
5. 채팅(WebSocket), 알림(SSE 등), 관리자, 광고, Kafka 로그 순서로 연결
6. 시연용 데이터와 더미 알림/채팅을 제거한 뒤 `DEMO_MODE`를 false로 전환

## 주의
- `DEMO_MODE=false`만 설정해도 API 연동이 자동으로 되지는 않습니다. 실제 이벤트 핸들러를 순차적으로 바꿔야 합니다.
- 비밀번호는 localStorage에 저장하면 안 됩니다. 서버에서 안전하게 해싱하세요.
- JWT를 쓴다면 쿠키 방식인지 Authorization Bearer 방식인지 먼저 결정하세요. 현재 클라이언트는 쿠키 인증 예시입니다.
- 위치 확인은 브라우저 권한과 HTTPS/localhost 환경이 필요합니다.
- 프론트엔드에서만 중복 확인하면 실제 중복 가입을 방지할 수 없으므로 서버 unique 제약과 검증이 필수입니다.
